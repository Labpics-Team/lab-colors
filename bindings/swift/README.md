# Lab Colors для Swift

[Подключение готового пакета и пример](DISTRIBUTION.md) не требуют Rust или
JavaScript. Пакет включает общий движок, сгенерированный UniFFI API и Swift
builder канонических Program-байтов. [Справочник API](../../docs/contracts/swift-binding.md)
описывает операции и жизненный цикл.

## Проверить изменение

Версии Rust, Swift, Xcode и образ Linux-потребителя задаёт
[worker](../../.github/workflows/native-conformance-worker.yml).
[Вызываемый workflow](../../.github/workflows/native-conformance.yml)
выбирает worker из той же ревизии. Обе проверки обязательны для PR:

* Linux: Rust-производитель собирает библиотеку из точного Git-снимка.
  Отдельный Swift-контейнер получает только готовую библиотеку, публичные
  Swift-файлы и тестовые данные, без исходников Rust и Cargo.
* Apple: создаётся самостоятельный SwiftPM-архив с XCFramework. Другой проект
  устанавливает архив, выполняет тесты на macOS и iOS Simulator и собирается
  для iOS-устройства. Физическое устройство этим прогоном не проверяется.

Скрипты находятся в `ci/`. `run-conformance.sh` требует объявленные
`RUST_TOOLCHAIN`, `SWIFT_TOOLCHAIN` и `SWIFT_IMAGE_V1`; `build-apple.py`
требует macOS с выбранным Xcode и `RUST_TOOLCHAIN`. Исполняйте их в CI,
используя настройки точной проверяемой ревизии.

Каталог `bindings/swift` является исходным пакетом разработки: файлы
`labcolors.swift`, заголовок и module map генерируются перед проверкой.
Не подключайте этот каталог как готовую зависимость стороннего приложения.
Самостоятельный пакет получается из `build-apple.py`.

## Полнота и одинаковые результаты

`native_surface.rs` сравнивает обнаруженные экспорты WASM и UniFFI, включая
число аргументов. Apple-проверка затем сверяет нативные операции и методы
публичных TypeScript builders с символами реально собранного Swift SDK.
Новая публичная операция не становится покрытой от одной записи в документе.

[Общие истории Program](../../conformance/program-runtime-v1.json) исполняются
через Rust FFI, Swift и JS/WASM. Независимые канонические байты сравниваются
с обоими языковыми builders. Тесты также проверяют отказы, повтор ревизии,
сохранение предыдущего состояния, повторный вход, смену потока и отзыв scope.

Четыре численных семейства [conformance-пака](../../conformance/README.md)
сохраняют собственные правила сравнения: численные поля с `driftTol`, композит
побайтно, HEX решателя в пределах ±1 единицы 8-битного канала.
Согласие не подтверждает пиксели неизвестного рендерера или восприятие человека.

## Измерить авторинг

Ручной запуск `Native conformance` принимает необязательный
`authoring_baseline`: полный SHA предыдущей реализации Swift builder.
После проверки установленного Apple SDK CI собирает предыдущий и текущий
builders в одном внешнем release-потребителе и чередует измерения. Сравнение
включает создание, кодирование, освобождение и точное равенство байтов.
Исходные выборки остаются в журнале, сводка в job summary. Оно не измеряет
скорость решателя или отрисовки UI.
