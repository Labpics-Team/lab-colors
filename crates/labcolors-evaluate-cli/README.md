# Оценка объявленной точки

`labcolors-evaluate` запускает существующий Program/TQ/CC/EVAL и выпускает LCEN
для **моделируемой sRGB8-точки** по явно выбранной конвенции. Он не измеряет
браузер, не подтверждает человеческое восприятие и не аутентифицирует отправителя.

## Первый запуск из исходников

Из чистого checkout репозитория с Rust версии, закреплённой `rust-toolchain.toml`:

```sh
cargo run --quiet --locked -p labcolors-evaluate-cli -- \
  crates/labcolors-evaluate-cli/examples/declared-point.json
```

Параметр `--quiet` отключает служебные сообщения Cargo, не меняя запрос к CLI.
Ожидается exit 0, пустой stderr и JSON с `terminalSrgb8: [128,128,128]`,
`ok:true` и `certificateHex`. Пример построен каноническим ProgramWireBuilderV1
и сверяется с ним в Core-тесте; встроенного preset в CLI нет.

```sh
cargo run --quiet --locked -p labcolors-evaluate-cli -- \
  crates/labcolors-evaluate-cli/examples/rejected-point.json
```

Второй вход имеет допустимый белый исходник, но запрещённую итоговую смесь.
Ожидается exit 4, пустой stdout и stderr с `clean-convention/rejected_by_convention`.
Это отказ явно выбранной политики, не универсальный закон красоты.

## Вход и результат

Файл необязателен: без него и с `-` читается stdin. `--format json` допускает
обычный JSON; `--format jsonl` требует ровно одну непустую строку и выдаёт одну
строку. Каждый запуск создаёт новый локальный attachment и не переносит чужое
состояние. Входные ProgramWire, привязка, observed-сценарии и профиль обязательны.
Неизвестные или повторные поля, неканонический hex и недостающий контекст
отвергаются, а не исправляются незаметно.

Схема версии 1 и все коды: [контракт интерфейса](../../docs/contracts/evaluation-cli-v1.md).
Пределы: 2 MiB на весь вход, 1 MiB на декодированную программу, 1–64 сценария,
до 4096 поверхностей на сценарий. Выход ограничен 8192 байтами. Это лимиты данного
адаптера, не параметры математических моделей. stdin ждёт EOF; ненулевой exit
означает, что частичный stdout необходимо отбросить.

Принимайте отчёт только **после завершения процесса с exit 0**, полного разбора
одного документа нужного kind/version и проверки обязательных полей. `--help`
также возвращает 0, но не выдаёт отчёт. `certificateHex` — переносимые недоверенные
байты: повторная проверка требует нового текущего EVAL. Это не бессрочное разрешение.

Стабильные группы кодов: 0 успех/помощь, 2 ввод, 3 неподдержанная область,
4 отказ оценки/выпуска, 5 I/O, 6 ограничение ресурсов/внутренняя ошибка.
Повтор после сбоя заново исполняет тот же запрос без внешних побочных эффектов.

Старый `labcolors-transport` остаётся отдельным транспортом 0/1 и не принимает
научный класс 4/2. Распространение готового бинарного файла и его аттестация
относятся к DIST-EVALUATE; команда выше использует проверяемые исходники.
