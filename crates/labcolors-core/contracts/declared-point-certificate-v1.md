# Сертификат объявленного точечного профиля V1

Внутренний владелец — `certificate/science.rs`. Это свидетельство текущего EVAL,
не доказательство человеческой чистоты или подпись отправителя. Единственный
внешний конверт — LCEN из `certificate.rs`, единственный источник совместного
результата — `authority/evaluation.rs`.

## Границы

Производитель принимает заимствованный `CurrentPointEvaluationV1`, а не RGB,
старые дескрипторы или произвольные хеши. EVAL уже удерживает оба исходника.
Выданный сертификат удерживает EVAL до последнего использования. Скопированные
байты остаются недоверенными; проверяющий модуль требует действующий EVAL,
удерживает его и именно проверенный буфер. Он не исправляет устаревшее AUTH.

Общий публичный `UntrustedEnvelopeV1::decode`, WASM и транспортный CLI продолжают
принимать только прежнюю пару `authority_kind=0 / payload_type=1`. Новый
внутренний вход использует тот же позиционный декодер с закрытым выбором 4/2.
Отдельные TQ/CC/HCE selectors 1/2/3 не переназначаются. Нового внешнего API нет.

## Кортеж LCEN

Схема/операция LCEN прежние: 1/IssueCertificate. Authority kind=4 означает
совместный объявленный точечный профиль, authority version=1; payload type=2,
payload version=1. Runtime artifact ID и producer revision получены тем же
build-дескриптором дерева Core, что в `certificate-source-tree-v1.md`.
Это идентичность исходного дерева, не гарантия бинарного файла или отправителя.

Producer content identity равна полной идентичности материала EVAL.
Context ID — ASCII `declared-modeled-point-v1:` и 64 lowercase hex символа
идентичности выбранного профиля EVAL. Свободные входные идентификаторы не принимаются.
Оба LCEN-домена SHA-256, positional framing и порядок отказов неизменны.

## Единственная полезная нагрузка

Все позиции фиксированы, integers big-endian, SHA-256 хранится как raw 32 bytes.

| Смещение | Байты | Значение |
|---:|---:|---|
| 0 | 4 | ASCII `LCPQ` |
| 4 | 2 | Версия 1 |
| 6 | 32 | Идентичность закона профиля из EVAL |
| 38 | 32 | Выпуск выбранной конвенции |
| 70 | 1 | Scope=1, моделируемая sRGB8-точка |
| 71 | 1 | Admission=1, DeclaredPackagePolicyCandidate |
| 72 | 1 | HCE=0, NotRequested |
| 73 | 32 | SHA-256 полного существующего кодирования материала AUTH |
| 105 | 1 | Ветвь TQ=1 |
| 106 | 96 | TQ release/applicability/provenance, по 32 байта |
| 202 | 1 | Ветвь CC=2 |
| 203 | 96 | CC release/applicability/provenance, по 32 байта |
| 299 | 3 | Конечный sRGB8 после композиции |

Длина ровно 302 байта. Нет вещественных чисел, optional-полей, человеческого
балла или порядка ветвей на усмотрение клиента. Кодирование материала не
дублируется: EVAL вызывает `authority::hash_modeled_point_identity`.

## Проверка

Полученные bytes сначала проходят общий ограниченный парсер класса 4/2,
затем фиксированные длину/версию нагрузки, точный кортеж текущего производителя
и побайтовое сопоставление с нагрузкой действующего EVAL. Одних правильных
хешей недостаточно. Новая ревизия при том же RGB, другое attachment, иной
источник Core, профиль или ветвь не принимаются. Результат ошибки не меняет
AUTH/attachment и не вызывает host.

Предел научного входа до выделения памяти: `MAX_TUPLE_BYTES_V1 + 302 + 32`.
Это прежний максимально допустимый кортеж, фиксированная нагрузка и завершающий
binding digest. Остальные ограничения LCEN сохраняются. Ошибки статические,
не содержат данных. Журнал допусков не создаётся: проверка не публикует эффект,
повтор того же корректного свидетельства остаётся проверкой, а не новой операцией.

Старые версии публичного транспорта отвергают новые селекторы. Нет скрытого
понижения до несмысловой полезной нагрузки. Удалённая аутентификация, подпись,
человеческая/полевая оценка и CLI-EVALUATE требуют отдельных контрактов.
