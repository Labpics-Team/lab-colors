# Измерить компиляцию и обновление цветов

Соберите `@labpics/colors` штатной командой из `packages/colors/package.json`.
Из корня репозитория запустите:

```sh
node packages/colors/bench/program.mjs packages/colors repeated 8 7
```

Аргументы: каталог собранного пакета, рисунок графа, число цветовых узлов,
число измерений после прогрева. `repeated` повторяет одинаковые цвета,
`distinct` задаёт разные, `shared` использует общий источник,
`grouped` распределяет узлы между четырьмя цветами.

JSON содержит исходные времена в миллисекундах, версию Node.js,
идентификатор исходников ядра, размер и SHA-256 WASM. Первое измерение
сохранено отдельно. Каждый цикл включает компиляцию, обновления фона,
чтение цветов, отказ при недостаточном контрасте, восстановление и освобождение
ресурсов. Время обновления включает чтение и проверку результатов.

Для сравнения подготовьте оба пакета и чередуйте запуски с одинаковыми
аргументами на одной машине. Сопоставляйте медиану и хвост распределения
по каждому рисунку графа; завершившийся тайм-аутом запуск сохраняйте как
незавершённый. Начальную загрузку и обновления сравнивайте отдельно от компиляции.
`maxRssKiB` отражает максимум памяти всего процесса, включая движок JavaScript.

Регрессия перебора повторяющихся компонент проверяется в тестах ядра числом
посещённых листьев поиска. Скорость конкретной машины в условие этого теста
не входит.

## Сравнить PR с его базой в CI

Добавьте PR метку `performance` перед следующим push. Штатное задание пакета
соберёт текущий snapshot и точный `base.sha` одинаковым toolchain и
`build_runtime`, затем запустит один и тот же consumer harness на одной машине.
Остальные проверки пакета сохраняются.

Артефакт `program-performance-<sha>-attempt-<n>` содержит идентификаторы базы,
проверенного snapshot и вершины PR, версии инструментов, SHA-256 обоих WASM,
исходные наблюдения и `summary.json`. Для каждого рисунка графа и размера
8, 64, 256, 1024, 4096 порядок запусков — база, изменение, изменение, база.
Каждый процесс сохраняет холодный цикл и три цикла после прогрева.

Один процесс ограничен 45 секундами, вся матрица — 480 секундами.
`timeout` и `budget-exhausted` означают незавершённое измерение; они остаются
в отчёте и не участвуют в отношении скоростей. Ошибка consumer assertions
завершает сравнение ошибкой. Отношение вычисляется только после завершения
обоих повторов обеих версий с совпавшими контрольными суммами.
