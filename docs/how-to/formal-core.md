# Формальная проверка ядра

Kani проверяет настоящий Rust-код Lab Colors. Проверочная сборка использует
`cfg(kani)`; обычная библиотека не получает новую зависимость или второй runtime.
Версия инструмента принадлежит `scripts/verify_core_formal.py`, перечень обязательств
и предметных отрицательных контролей находится в `scripts/formal_contracts.py`.

## Области доказательства

| Область | Проверяемое свойство | Точный предел |
|---|---|---|
| AUTH | Полная привязка разрешения, атомарный отказ, изоляция трёх ячеек, CAS, повтор и полезная цепочка вызовов | Произвольные 256-битные идентичности; истинность доказательства владельца принята как вход. Только текущий `Unverified` |
| Hex | Строгая грамматика без знаков `+`, правильный разбор обоих полубайтов, сохранность всех sRGB8-цветов | Любые байты строк длиной 0–8; полная принимаемая грамматика 6/7 байт. Более длинная строка отвергается структурным сопоставлением |
| Прозрачность | Весь binary64-допуск `[0,1]`, канонизация `-0`, точный предшественник, замкнутые интервалы и их принадлежность | Все 64 бита каждого входа, включая нечисла, бесконечности и субнормальные значения |
| Композиция | Замкнутость умножения любых двух канонических opacity; точные законы 0/1; диапазон source-over до округления и его граничные случаи | Полный канонический binary64-домен каждого множителя, включая округление слишком малого произведения в ноль; произвольная допустимая opacity для 0/1; любые пары байтов канала для концов source-over. Дополнительно доказана неизменность одинаковых source/backdrop при любой допустимой binary64 opacity. Полный домен байтов source/backdrop и канонической binary64 opacity также даёт конечное значение `[0,255]` до округления и приведения к байту; монотонность этим не доказана |
| Сертификаты | Точные границы чтения, отсутствие переполнения смещения, неизменность курсора при отказе `read_exact`, big-endian, длина, версия SHA | Буфер 8 байт и произвольные машинные offset/length; вся 40-байтовая grammar revision. Не полный двухмегабайтный конверт или SHA-стойкость |
| Program wire | Little-endian, отказ без сдвига курсора, сохранность всех битов f64, точный лимит количества записей | Буфер 8 байт, полный usize/u32/u64-домен проверяемых полей. Сырые NaN-биты допустимы в транспорте, не в opacity |
| Контраст WCAG | Точные точки дают исходную несокращённую дробь; решение интервала верно для любой заключённой пары целочисленных Q55-точек; полярность не меняет результат | Q55-границы `[0, 2^55+3]`; все четыре текущих критерия. Таблица яркости имеет отдельное полнодоменное численное доказательство |
| Совместный выбор | Только полный порядок без повторов, сохранность приоритета клиента, отказ при чужом ordinal и переполнении удвоения cardinality | Kani: два элемента и полные usize-ординалы; Обычные исчерпывающие тесты: 12 shape-отказов и все 256 последовательностей пар из 2×2, не выборка. Переполнение: произвольная cardinality × 2 |
| Идентичность observation | Совпадающих stream/revision недостаточно: evidence должно ссылаться на тот же backing | Полные u32 stream, u64 revision, настоящий pool/Rc и два разных backing либо alias; payload не читается проверяемым predicate и в этом harness пуст |
| Session | Текущее evidence существует только в Ready; последнее хорошее не получает текущие полномочия; вытеснение сохраняет принадлежность обоих payload | Все варианты состояния и произвольные u64 payload-идентичности; не доказательство пользовательских деструкторов или полной истории Session |
| Replay ledger | Точный бюджет записей и байтов, без переполнения и ошибочного отказа на допустимой границе | Полные usize-домены количества, учтённых байтов и длины новой записи; память и разбор конверта проверяются отдельно |
| Sink stamp | CAS сохраняет ожидаемый token, следующий номер равен предыдущему + 1 с прежней эпохой; переполнение даёт отказ | Полные u64 sequence и все ненулевые u64 эпохи; это используемый Attachment-stamp, не старый staged автомат |


| Полевой пиксель | Точный допуск premultiplied RGBA8; законы source-over и lighter с сохранением `RGB ≤ alpha` | Все восемь входных байтов двух пикселей. Source-over возвращает единственный ближайший целый к несокращённой дроби со знаменателем 255; lighter насыщает каждый канал, включая alpha |
| Геометрия поля | Непустой прямоугольник, точное расширение на радиус и обрезка по extent; чужая геометрия и переполнение отвергаются | Полные u32 координаты, размеры и radius на допустимых extent Linux x86_64. Overflow остаётся ошибкой даже при последующей обрезке |
| Граница размытия | ClampToEdge выбирает точную допустимую координату без переполнения | Полные u32 coordinate/radius/limit и usize index; limit ненулевой, coordinate внутри него. Это арифметика выборки, не доказательство произвольного фильтра |


| Передача результата хосту | Точный допуск команды, отсутствие публикации до install, атомарный отказ и повтор, однократный успех, отказ старого stamp до вызова хоста | Реальный handoff-writer после admission; полные u64 sequence/revision/ненулевой epoch, u32 ID, RGB и каноническая binary64 opacity. Patch-длины 0/1/2; более длинные отвергает тот же slice-pattern. Хост моделирует только контракт атомарного порта, не браузер |


Взаимосвязанные слои сохраняются: эмпирическая модель, её численная реализация,
транспорт и полномочия не удостоверяют друг друга. В частности, формальное
доказательство не превращает математический критерий в человеческий закон чистоты.

## Запуск

В разрешённой Linux x86_64 среде проверок с Rust и Python 3.11+:

```sh
cargo install kani-verifier --version "$(python3 scripts/verify_core_formal.py --kani-version)" --locked
cargo kani setup
python3 scripts/test_verify_core_formal.py
python3 scripts/verify_core_formal.py --output-dir /absolute/scratch/core-formal
```

Используется отдельный одноразовый checkout. Положительный прогон исполняет все
Kani-harness ядра: исчезнувшее или незарегистрированное доказательство меняет точный
набор и блокирует допуск. Именованные утверждения должны пройти, все обязательные
положительные и отрицательные исходы должны быть достижимы. Недостижимая защитная
ветка, сгенерированная компилятором, допустима; недостижимое обязательство не допустимо.

Затем по одному исполняются предметные мутации: неполная идентичность AUTH,
допуск `+` в hex, сохранение отрицательного нуля, неправильное смещение reader,
исключение допустимой границы wire, ослабленный порог контраста и пропуск дубля
совместного порядка, подмена backing observation, неверная граница ledger, повышение
исторического evidence, отсутствие продвижения sink-stamp, подмена умножения opacity сложением и неверный знак в source-over до приведения к байту. Нужен контрпример к именованному свойству. Ошибка компиляции,
памяти, тайм-аут или посторонний panic не засчитываются как найденный дефект.

JSON-отчёты, логи, воспроизводимые контрпримеры и квитанция V2 с именованными
дайджестами отрицательных контролей сохраняются
артефактом задачи `formal core (Kani)` внутри обязательного CI. Публикация требует
эту задачу в успешном canonical push-run точного коммита. Старый результат не
подменяет новый запуск. Нечистый checkout не получает `source_commit` в квитанции.
При проверке чистоты локальный Git fsmonitor отключается, целостность достижимых
объектов Git проверяется через `git fsck --strict`, а сырые байты всех
отслеживаемых файлов сравниваются с blob указанного коммита. В том числе
`verified_source_sha256` формальных исходников привязаны к этим blob.
Физическое поддерево `crates/labcolors-core` дополнительно сверяется с Git-деревом,
включая игнорируемые файлы и пустые каталоги; workspace `target/` остаётся допустимым.
Отслеживаемые символьные ссылки внутри Core и среди формальных входов вне Core
отклоняются: Git связывает текст ссылки, а компилятор или верификатор может прочитать
изменяемую игнорируемую цель. Посторонние ссылки вне Core остаются допустимыми.
Это обнаруживает правку, скрытую настройками статуса или индексом Git. Checkout,
меняющий байты исходников при извлечении, не получает `source_commit`. Для Linux CI
нужен checkout с LF: перевод LF в CRLF при извлечении также не совпадёт с blob. Для этой
проверки нужен Git 2.35.2 или новее: более ранние версии трактуют
`core.fsmonitor=false` как путь к hook, поэтому верификатор завершится отказом.

## Обновление и пределы

Проверки развёртки циклов и достижимости не отключаются. У каждой proof с циклом
граница указана атрибутом; её нехватка даёт отказ, а не доказательство. Обновление
форматов, вариантов перечислений или размеров требует повторной оценки области.
Новая ветвь renderer не считается проверенной прежним `Unverified`-доказательством.

Штатное исключение восстанавливает изменённый для мутации файл. Тайм-аут завершает
всю группу решателя. Принудительное убийство Python или хоста не выполняет `finally`,
поэтому на рабочем checkout проверки не запускаются. Выделение памяти считается
успешным по стандартной модели Kani; исчерпание памяти проверяется другими тестами.

Kani, его компилятор, решатель и машинная семантика остаются доверенной базой.
Это не Lean-теорема о любой платформе. Замкнутость произведения двух opacity
доказана на полном каноническом binary64-домене: входная область задаётся порядком
битов уже допущенного значения; правильность конструктора доказана отдельно.
Более сильное утверждение «произведение не превышает ни одного множителя»,
отсутствие пропуска байта между соседними источниками при любой opacity и
произведение двух произвольных cardinality пока не имеют завершённого
символьного доказательства: попытки достигли ресурсного предела. Замкнутость
не подменяет эти утверждения. Остальные типы цветовых преобразований продолжают
проверяться независимыми численными эталонами, полным конечным перебором и тестами.


## Связка математического решения с живым путём

`session/lifecycle_tests.rs` исполняет настоящие Session, observation, arena и
prepare/commit/drop. Доменный evaluator здесь явный тестовый потребитель: его
исходом может быть Verified, Violation, ошибка или чужое evidence. Цветовая
математика этим тестовым evaluator не подменяется и не утверждается.

Матрица охватывает начальные и граничные ревизии вплоть до u64::MAX, одинаковый
и чужой stream, изменение значения и provenance, потерю владельца, оба пути ввода,
обычный и отложенный commit, отказ и отмену. Отдельные истории проверяют старое
подтверждение для нового состояния, четыре отмены подряд при трёх arena-слотах,
возврат из Unknown/Violation и невозможность выдать последнее хорошее за текущее.
Это исчерпывающие заданные классы, не все возможные истории или цвета.

`certificate/lifecycle_tests.rs` проверяет настоящий ledger, в том числе producer →
decode → admission на границе 1024 ключей. Точный повтор остаётся допустимым в
заполненном ledger, новая запись отвергается. Для проверки всех байтов attestation
и арифметических границ используются также явно обозначенные post-decode входы.

Существующий `authority_mutation_gate.py` дополнен подменами вызывающего кода:
пропуск проверки связи evidence с observation, пропуск проверки порядка и обход
расчёта бюджета. Они обязаны сломать реальные lifecycle-тесты. Таким образом,
зелёная проверка отдельно стоящего helper не подменяет его включение в продукт.

Порядок ревизий в production сохранён без рефакторинга: вынесение общей проверки
увеличило runtime WASM на 11 байт, а декларации inline не устранили рост.
Математическая проверка связи evidence с observation не требует такого изменения.

Единая символьная проверка heap/Rc-пути Session и replay-ledger ранее достигла
180-секундного предела решателя. Более сильные свойства порядка source-over
также пока не доказаны. Его диапазон до округления теперь доказан отдельно.
Тайм-аут означает неопределённый результат, не найденный дефект и не PASS.
В обязательный CI включены только завершённые доказательства указанных законов;
сквозные свойства отдельно защищены реальными тестами.


## Граница разрешимости прозрачного цвета

`point_representation/frontier_tests.rs` проверяет все 65 536 пар байтов
«целевой канал/фон». На найденной границе и её следующем представимом значении
эталонный поиск перебирает все 256 источников; на предыдущем представимом значении
не должно существовать ни одного. Допустимая фиксированная прозрачность сохраняется,
недопустимая даёт типизированный отказ. Эталонный перебор не использует поисковый
алгоритм или его проверку крайних источников, но пользуется тем же объявленным
композитором: проверяется поиск, не иной отрисовщик.

Отдельно проверены 65 536 перекрёстных RGB-случаев: первая общая opacity должна
равняться максимуму трёх поканальных границ. Это не все 2^48 пары RGB и не все
промежуточные binary64 opacity. Включённые в штатный native mutation gate подмены
«любой канал вместо всех» и «выбрать верхнюю границу вместо минимальной» обязаны
сломать этот конкретный тест, а не произвольную проверку или компиляцию.


## Полный растр и частичное обновление

`field_effect/raster_tests.rs` вызывает настоящие `evaluate_reference_full` и
`evaluate_reference_incremental`. Для всех размеров от 1×1 до 5×5, всех непустых
прямоугольников изменения и четырёх поддерживаемых DPR при радиусе один CSS-пиксель
исполнены 4 900 сценариев. Дополнительно все 33 допустимые пары CSS-радиуса и DPR
(радиус устройства до 16) проверены на трёх геометриях, включая изображение 1×1.
Прямой 2D-эталон строит биномиальные коэффициенты сложением соседей и считает целочисленную
свёртку с единственным округлением. Он не использует Q32-таблицу, два прохода,
выборку или расчёт области влияния из production. Это конечная матрица геометрий
и заданных неоднородных пикселей, не перебор всех возможных изображений.

Сравниваются каждый пиксель, полная и частичная перерисовка, область влияния,
неизменность пикселей вне неё и переиспользование выделенных буферов. Изменение
за пределами объявленной области должно отказать без порчи результата; правильный
повтор после отказа принимается, а прежний запрос после успеха уже не подходит.
Потребители source-over/lighter проверены также на шести разных RGBA-пикселях:
оба изменяемых входа контролируются независимо, не только передний слой.

Пять новых формальных подмен нарушают насыщение пикселя, округление,
допуск пустого прямоугольника, область влияния и координату у края. Три native-подмены
убирают ореол размытия, проверку скрытого изменения или округление свёртки. Каждая
обязана нарушить именованное свойство или конкретный тест, не просто сломать запуск.

Первоначальная объединённая проверка двух операторов с делением в oracle достигла
180-секундного лимита. Разделение обязательств и проверка остатка вместо повторного
деления сохранили полный домен и позволили завершить source-over proof. Знаменатель
255 нечётный: условия `|255·output − numerator| ≤ 127` задают единственное ближайшее
целое, а не допуск к иной формуле. Корректность компилятора и решателя остаётся
предпосылкой; совпадение с отрисовщиком браузера этим срезом не утверждается.


## Передача проверенного результата приложению

`program/attachment/handoff/proofs.rs` проверяет настоящие `prepare`, `try_install`
и завершение записи. Символьное состояние охватывает начальный writer, опубликованный
цвет и отозванный цвет; подтверждение допустимо и при исчерпанном sequence, потому
что оно не меняет его. Ошибка хоста сохраняет прежнее состояние и подготовленную
команду; повтор остаётся возможен, успешная команда потребляется однократно.
Отдельная проверка старого stamp намеренно допускает внутренний drift, запрещённый
обычным эксклюзивным Rust-заимствованием: это защита install, не найденная гонка.

Внешний host-порт в proof реализован моделью «всё или ничего». Его атомарность
является предпосылкой; выдача epoch, реальные browser callbacks, произвольная
конкурентность и весь Session-граф этими тремя доказательствами не проверяются.
Цикловая граница 4 достаточна для сравнения трёх RGB-байтов; проверка её полноты
включена, недостаточная развёртка не считается ни product bug, ни PASS.

Связку с Session и правом выдавать render-output проверяет тест
`exhaustive_handoff_histories_keep_host_session_and_authority_in_sync` в `handoff.rs`.
Это все 1 372 истории длины три из семи событий для двух начальных состояний и двух
границ ревизии (0 и последние три перехода до u64::MAX). Успешные set/revoke,
точные повторы, устаревшие или противоречивые запросы и отказы каждого вида операции
сопоставляются с состоянием host, Session, stamp и текущими render-outputs.
Фиксированная программа и контрактная модель host здесь явные ограничения,
не утверждение о всех программах или неограниченных историях.

Отдельно проверены четыре unwind до публикации подряд и успешный повтор после них:
prepared-состояние не теряется после исчерпания числа arena-слотов. Это не обещание
восстановиться после хоста, который нарушил контракт и упал уже после публикации.
Четыре формальные мутации ловят чужое подтверждение, проглоченный отказ, повторное
исполнение и старую подготовленную команду. Две native-мутации отдельно проверяют,
что вызывающий Attachment действительно фиксирует Session и сохраняет новый stamp.


## Независимые критерии контраста

Интервальный контракт WCAG проверяется четырьмя обязательными harness по каждому
текущему критерию. Все используют один прежний предикат над шестью произвольными
Q55-значениями: двумя интервалами и точкой внутри каждого. Во всех частях остаются
sound PASS, sound FAIL, симметрия и достижимость трёх исходов, включая неопределённость.
Это конъюнктивное разбиение конечного выбора критерия, не уменьшение области чисел
или утверждений. Отсутствие любой части блокирует допуск, даже если подправлен
счётчик успешных проверок. Лимиты решателя и проверки переполнений не меняются.

Отдельная мутация заменяет консервативные края интервала оптимистичными при выдаче
PASS. Нужен контрпример к всеобщему утверждению о внутренних точках; корректная
проверка только точечных интервалов сама по себе такую подмену не обнаружила бы.


## Явный выбор конвенции конечного цвета

`authority/clean_convention/proofs.rs` проверяет настоящий `select` на любых
32 байтах выпуска и всех вариантах области/допуска. Принимается ровно текущий
выпуск моделируемой sRGB8-точки с `DeclaredPackagePolicyCandidate`. Полезный
исход и три отказа имеют обязательные свидетели достижимости. Подмена проверки
допуска обязана дать именованный контрпример, не ошибку компиляции.

Это доказательство границы выбора, не таблицы чистых цветов или человеческого
восприятия. Настоящий CC-вызов отдельно проверяется через ProgramAttachment:
классифицируется конечная композиция, сохраняются текущая привязка, точный CAS
и независимость TQ/HCE. Контроли в `authority_mutation_gate.py` подменяют исходный
цвет вместо итогового, скрытый выбор по умолчанию, отказ всем, ветвь AUTH и
привязки доказательства. Старые AUTH/TQ-проверки сохранены; кодирование точки
переиспользуется обеими ветвями без нового владельца состояния.


## Свежая совместная оценка и заимствование результата

Общий оценщик использует прежние владельцы TQ/CC. Его предметные подмены в
`authority_mutation_gate.py` проверяют отсутствие каждой ветви, доверие старому
описанию при том же RGB, потерю ветви в результате и отказ всем. Положительные
проверки исполняют настоящий attachment; конечные истории фиксируют доступность
и ревизии независимо от кодировщика доказательств.

Тот же гейт компилирует временные пробы внутри настоящего модуля оценщика.
Изменение attachment или AUTH до последнего использования результата должно
дать именно `E0502` в этом модуле; после последнего использования оба изменения
компилируются. При намеренной подмене времени жизни результата на `'static`
запрещённое использование компилируется: это контрпример к отвязанному результату,
а не успешная проверка такого изменения. Исходник восстанавливается после каждой
пробы. Проверка опирается на компилятор Rust, не на отдельную модель состояний.

Новые проверки не расширяют математическую область Kani. Существующий формальный
набор сохраняется; моделируемая точка, объявленная политика и внутренний результат
не выдаются за полный растр, человеческое восприятие или переносимый сертификат.


## Сертификат действующего EVAL

`scripts/science_certificate_gate.py` исполняет научный производитель на чистом
Git-источнике. Подмены получают отдельные локальные коммиты во временном worktree:
иначе незакоммиченный источник правильно дал бы отказ идентичности, не предметный
контрпример сертификата. Исходный HEAD/файлы не меняются, временные экземпляры
не публикуются и удаляются. Все прежние AUTH/TQ/CC/EVAL-контроли сохранены.

Независимые пробы меняют привязку кортежа, тело с правильными хешами, материал,
каждую ветвь, принятие общего транспорта и отказ всем. Пять проб компилятора
различают удержание AUTH/attachment/проверенного буфера и их освобождение после
последнего использования. Отказ засчитывается только на соответствующей строке
мутации, а не по любому ненулевому коду сборки. Это не новые Kani-теоремы.
