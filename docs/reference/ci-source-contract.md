# Исходники и процедура CI

**Diátaxis:** справочник.

CI исполняет разрешённые исходники Labpics. Служебный ID репозитория GitHub и
репозиторий головы PR проверяются в обязательном `source-admission` до загрузки
кода. Чужая голова PR получает `REFUSED`; отсутствующие или неверные служебные
данные GitHub — `INCOMPLETE`.

Запись допуска различает SHA события, голову PR, вызывающий файл и выполняемую
процедуру, её репозиторий, путь и ref, запуск, попытку, check-run и раннер.
Поля `job.workflow_*` идентифицируют файл, определяющий задание;
`github.workflow_*` относятся к вызывающему файлу. Сборка и квалификация
всего конвейера требуют своих проверок. Управляющие символы отклоняются до
записи полей в `GITHUB_ENV` и `GITHUB_OUTPUT`.

В режиме LOCAL bootstrap вызывающий файл и процедура сохраняют один снимок.
Существующая проверка `ci_workflow_binding.py` сравнивает байты вызывающего
файла, CI worker и package worker с этим снимком; отдельно сохраняется точный
SHA загруженного кода. Временный допуск GitHub по FULLSHA относится только к
проверенной неизменяемой процедуре.

Тяжёлое задание требует `self-hosted` до исполнения исходников. Другой раннер
получает явный отказ. Проверки ОС, инструментов и настоящего потребителя остаются
обязательными. Проверка служебных данных не подтверждает работу Android, Apple,
WASM или потребителя. Лёгкое задание публикации использует `github-hosted` для
доверенной OIDC-публикации npm.

`full-domain-run.yml` с `guard_only=true` проверяет служебные данные GitHub
и отказ при подставленной чужой голове PR в LOCAL reusable worker. Этот запуск
не создаёт доказательство всей области. Значение по умолчанию сохраняет полное
доказательство.

Proof-задания сохраняют native-проверки исполнителя и точного размещения
observer в делегированном cgroup. Они не меняют общие настройки AppArmor и
`core_pattern`. Имя cgroup включает задание; приватное делегирование требует
проверки ядром и успешного native-запуска.

До `npm publish` сохраняются точные успешные main/push-запуски, реальные
обязательные задания и все выполненные вызываемые процедуры, привязанные к
SHA выпуска. Успех другой процедуры или исходника не квалифицирует изменённый
граф и закреплённые версии инструментов.

Bootstrap-процедура явно отказывает перед `npm publish`. Разрешение выпуска
появляется только в отдельно квалифицированном срезе protected-main.
