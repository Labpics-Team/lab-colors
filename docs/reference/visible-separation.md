# Расстояние между видимыми цветами

`ProgramWireBuilderV3.visibleSeparationHard(id, occurrence, minimum, maximum)`
задаёт включённый диапазон расстояния между финальным encoded visible цветом
occurrence и её фактическим encoded backdrop. Оба цвета берутся после выполнения
объявленного графа композиции. Прозрачность Paint и поверхности из других
occurrence входят в эту физическую модель.

`minimum` и `maximum` — конечные числа с
`0 <= minimum <= maximum <= 2`. Границы задаёт клиент. Этот диапазон — область
admission API; значение `2` не является эмпирическим порогом качества.
Нулевые значения канонизируются, оба порога входят в content identity.
Wire V3 использует constraint tag `11`; V1 и V2 его не принимают.

## Численный контракт

Core переводит оба encoded sRGB8 цвета в linear sRGB и затем в Oklab с
матрицами 2021-01-25 из [первоисточника Björn Ottosson](https://bottosson.github.io/posts/oklab/#converting-from-linear-srgb-to-oklab).
Расстояние вычисляется непосредственно в `f64` как
`sqrt((L1-L2)^2 + (a1-a2)^2 + (b1-b2)^2)`, в масштабе Oklab с белым `L` около `1`.
Для точечного вывода обе границы `distanceBounds` равны этому опорному
`distance`. При неточной растровой эмиссии Core вычисляет диапазон расстояний,
включающий погрешность обоих цветов. Hard verdict требует
`minimum <= distanceBounds[0]` и `distanceBounds[1] <= maximum`, без epsilon
и без пересчёта порогов в другой численной форме. Опорное расстояние может
попадать в авторский диапазон, а ограничение всё же получить violation, если
граница с учётом точности вывода выходит за него. Закон переноса погрешности
описан в [точности вывода материала](../explanation/material-emission.md).

Ограничение выражает выбранную клиентом геометрическую policy. Оно не
сертифицирует JND, читаемость, WCAG, «чистоту» или предпочтение наблюдателя.
Для этих свойств нужны собственные независимые ограничения и основания.

## Решение и evidence

Fixed Paint проверяется в объявленной композиции. Для computed Paint это
ограничение пересекается с остальными hard constraints до выбора; перед Ready
Core ещё раз проверяет выбранный tuple на всех актуальных физических cases.
При несовместимости ограничений свежие outputs отсутствуют.

В `assessmentReport()` клетка имеет `kind: "visible-separation"`, `verdict`,
`visible`, `backdrop`, `distance`, `distanceBounds`, `minimum` и `maximum`. `constraintId` и
`caseIndex` принадлежат внешней клетке отчёта. Это сохранённые данные завершённой
оценки; изменение скопированного отчёта не изменяет состояние runtime.

Wire также допускает tag `11` в report-only секции: измерение сохраняется в
отчёте, но его violation не запрещает выбор. Метод `visibleSeparationHard`
записывает только hard секцию.

## Два применения на своих подложках

`colors().separate(left, right, [minimum, maximum])` сравнивает два различных
применения после композиции каждого со своим фоном. При смене окружения Core
подбирает обе краски в общей задаче и проверяет диапазон на каждой паре
конечных цветов одного физического сценария. Порядок пары не меняет условия.
Оба применения могут быть адаптивными. Ссылка на исходное окружение необязательна.

В wire V3 метод `visiblePairSeparationHard(id, left, right, minimum, maximum)`
записывает в секцию обязательных условий tag `14`, два ID occurrence и обе
границы binary64. Численная модель и единицы те же, что у `visibleSeparationHard`.
Для каждого материала учитывается собственный допуск эмиссии. Если оба допуска
нулевые, `distanceBounds` содержит точечное расстояние. В остальных случаях
используется консервативная оценка для обеих областей encoded sRGB8. Если
применения наследуют один физический пиксель через полностью прозрачные слои,
его расстояние до самого себя точно равно нулю.

В `assessmentReport()` клетка успешной пары имеет `kind: "visible-pair-separation"`,
`left` и `right` с итоговыми RGB8 в порядке объявления, `distance`,
`distanceBounds`, `minimum`, `maximum` и `verdict`. Как и у сравнения с
подложкой, границы задают выбранную автором степень геометрического различия.
