# ADR-0001. Конфиг-граница: физика в движке, семантика в конфиге потребителя

Статус: предложено (2026-07-02). Решение владельца об архитектуре зон —
2026-07-02: «цвета агностичны, чтобы ими пользовались разные ДС с разной
семантикой; каждое в рамках своей зоны; система для любого клиента студии:
взял → закастомил быстро → внедрил».

## Решение

Движок не знает ни одного имени роли и ни одного брендового значения.
Всё, что меняется при смене клиента студии, — конфиг потребителя
(`ThemeConfig`); всё, что является законом восприятия/математикой/WCAG, —
физика ядра. Правило одного вопроса для каждой единицы: **«изменится ли это
при смене клиента?»**

Основание — инвентарь семантики ядра (2026-07-02, main@31643d9): единственный
load-bearing продакшн-hex движка — 10 якорей `Accent::anchor_hex`
(accent.rs:115-124); эмиссия — ровно 20 ролей из запечённого
`RoleTable::default()`; кэш WASM уже ключуется `table_fingerprint` (cache.rs) —
сеам под конфиг существует.

## Схема ThemeConfig (сущность; полная спека — при реализации CH-02)

- `brand.anchor` (hex; hue выводит физика) — дефолта в ядре нет.
- `neutral.anchors {light, mid, dark}` (hex-тройка: конфиг несёт ИЗМЕРЕННОЕ,
  движок выводит производное — hue, кривую) + ручки подтона
  (`ratio`, `target_mp`, `hue_stiffness`).
- `palette[]` — N семейств `{key, anchor}` (labui: 10 замеренных).
- `sentiments` — категории потребителя → семейство + политика
  (`hue_floor_deg`, `preferred_side`, `hardness`, `chroma_fraction`).
  `S_PERC_MIN` движок ПЕРЕСЧИТЫВАЕТ из конфиг-якорей (закон
  `2·C_rep·sin(10°)`, Witzel & Gegenfurtner 2013) — не константа.
- `themes` — словарь `имя → VC-пресет` из закрытого физического меню
  (`srgb | dim | srgb_ic | dim_ic`); произвольных VC-чисел в конфиге нет.
- `roles` — имя → рецепт из физического меню:
  `text_anchor(fraction, floor)` · `dj_anchor(light, dark)` ·
  `ladder(brand|family|sentiment|neutral, position)` ·
  `alpha_analog(of, alpha)` (композит-инверсия, alpha.rs) · `zero`.
- `aliases` — компонентные алиасы на существующие роли.

Имена ролей — произвольные строки (`[a-z0-9-]+`), эмиссия `--lab-{имя}`
существующей механикой. Коллапс-контракт исполняется схемой: в конфиге labui
нет `static-*/inverted-*/on-*/mat-*` — роли решаются от фактического фона.

## API

- Ядро: `RoleTable::from_config(&ThemeConfig) -> Result<RoleTable, ConfigError>`;
  `resolve_set(bg, &table, vc)` — без изменений.
- WASM: `engine.load_config(json) -> fingerprint`; сигнатура
  `resolve_theme(bg_hex, theme)` НЕ меняется — конфиг = состояние движка,
  кэш по fingerprint.
- Ручки политики (TINT_TARGET_MP, CHROMA_FRACTION, HARDNESS,
  IC_DECORATIVE_FLOOR_MIN, …) экспонируются конфигом с сегодняшними значениями
  как дефолтами конфига labui; каждая остаётся SSOT-TRACKED в науч-реестре.
  `slope 0.15` (scale.rs:39) НЕ экспонируется — декларируется физикой в
  реестре (научная задача — вывести или обосновать).

## Судьба golden-lock

240-строчный owner-approved golden (semantic.rs:3352-3655) пинит ПАРУ
«физика × семантика labui» — после конфиг-границы он переезжает в labui как
пин ЕГО конфига на живом движке. В ядре остаётся физический golden
(golden_tests.rs: CIECAM16 против colour-science, Lc против apca-w3).
До переезда: тест ядра держит текущую эмиссию против labui-конфиг-фикстуры
(байт-в-байт — golden-совместимость доказуема на каждом шаге).

## Последствия

- Агностичность доказуема исполнением: второй конфиг (иные имена/якоря/темы)
  резолвится без правки кода — демо входит в exit-criteria поезда.
- Ломающие изменения ядра отложены за зелёный поезд (шаг 4) — ни одного дня
  без работающей пары.
- Двойной enum тем (wasm/theme.rs и cleanliness.rs) унифицируется в PR-a.
- Нейминг теней канонизирует конфиг labui (`fx-shadow-*`); переход теней на
  альфа-якоря (@1/@2/@4/@12 через alpha_analog) — отдельное научное решение,
  вне поезда.
