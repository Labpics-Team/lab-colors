# Характер и качество цвета

Хорошая цветовая система сохраняет узнаваемые роли, согласует поверхности,
помогает различать элементы и поддерживает целую композицию при изменении
контекста. Эти задачи связаны, но у каждой есть собственные настройки.

В Lab Colors исходный цвет задаёт характер роли. Местное применение связывает
его с поверхностью и назначением. Core выбирает весь набор вместе: изменение
заливки учитывается при выборе надписи, а прозрачный материал оценивается
после наложения. Поэтому качество описывается отношениями внутри системы.

## Что чем управляет

| Задача | Средство в цветовой системе |
| --- | --- |
| Сохранить узнаваемый оттенок | Исходная опора роли и `identity` |
| Ограничить силу изменения | `maxChange` от исходной опоры |
| Выстроить поверхности | Собственные тональные кривые и отношения вложенности |
| Сделать элемент более или менее заметным | `separation` относительно фактического фона |
| Сделать текст или графику достаточно контрастными | Выбранный критерий `contrast` |
| Сохранить характер прозрачного слоя | Выбор исходника по конечному видимому цвету |
| Согласованно обновить интерфейс | Одно принятие фона и всех связанных значений |

Условия применяются к одной композиции. Среди пригодных вариантов предпочтение
определяется близостью к опоре: исходному цвету роли либо результату её
тональной кривой. `maxChange` при этом сохраняет привязку к исходному цвету.
Так ссылка может адаптироваться к фону, а поверхности следовать правилам
дизайн-системы, сохраняя общий замысел.

Связи нынешнего API описывают общую цветовую опору и наложение: `.on(surface)`
задаёт реальную подложку, `separation` сравнивает применение с этой подложкой.
Самостоятельное требование к различимости двух соседних применений этим API
пока не задаётся. Имена ролей такого отношения не добавляют.

## Оценивать результат в композиции

В [интерактивном примере](../../examples/contextual-colors/README.md) можно
проверить связанные заливку, надпись и ссылку, отдельный лист и прозрачный
материал на разных фонах. При изменении правил сравнивайте целый интерфейс:
сохранился ли характер акцента, порядок поверхностей и различие назначений,
насколько материал соответствует выбранной прозрачности. Проверка контраста
покрывает своё условие внутри этого результата.

Успешный расчёт означает выполнение объявленных условий. Решение о качестве
самих правил опирается на видимые сравнения и относящиеся к задаче исследования.
Такая оценка может изменить настройки, критерий выбора или сам способ
описания системы.

## Исследования cleanliness

Число **36** относится к участникам одного исследования
[Sato и Inoue, 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC5149061/):
они оценивали 32 одиночных цветовых стимула на сером фоне. Эти данные входят
в отдельную номинальную модель clean-set. Полное воспроизведение этой модели
проверяет вычисление её результатов для sRGB8; размер цветового пространства
не меняет размер исходной человеческой выборки.

Исследовательский архив проекта значительно шире. В
[CLEANLINESS-EVIDENCE](https://github.com/Labpics-Team/agents-config/blob/0111fcf89a44afe182e533354ed3c358b93cce22/plans/lab-colors/reference/CLEANLINESS-EVIDENCE.md)
сопоставлены 56 исторических записей: работы о направленных изменениях цвета,
оценках полей, целых визуальных представлений и зависимости оценки от контекста.
Там сохранены как полезные результаты, так и контрпримеры. Это разные задачи
и выборки; число записей не является числом независимых исследований.

Архив помогает выбирать и проверять правила: результаты по одиночным цветам
относятся к характеру роли, а работы о полях и расположении цветов — к оценке
композиции. Перед переносом конкретного вывода важны исходная задача,
условия предъявления и сохранённые контрпримеры. Отчёт по Sato и Inoue даёт
один срез этой базы. [Инвентарь численных политик](../empirical-inventory.md)
отдельно описывает константы в коде и их происхождение.

В рабочем API характер цвета задаётся геометрической политикой `identity`,
а поверхности, материал и назначение участвуют в решении вместе. Политика
по умолчанию — изменяемый выбор дизайна, описанный в
[модели системы](color-system.md#характер-и-свойства-применения).
Её коэффициенты не выведены из 36 участников. Бинарный clean-set подключается
отдельно через низкоуровневый Program; обычная декларация роли его не включает.
Автоматическое отношение `Cleaner`/`Dirtier` между результатами нынешний
authoring API не вычисляет. Сохранённый корпус контекстных отношений и
человеческие наблюдения остаются основаниями для исследования таких правил.

См. [модель цветовой системы](color-system.md),
[воспроизведение nominal clean-set](../how-to/reproduce-nominal-clean-set.md)
и [контекстные отношения cleanliness](../decisions/0004-cleanliness-relation-order.md).
