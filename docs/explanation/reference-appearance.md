# Адаптация исходной композиции

Исходный цвет имеет смысл вместе со своим окружением и материалом. Минимум
контраста отвечает на вопрос о допустимости; он не выражает, насколько сильным
дизайнер сделал цвет. Поэтому `reference` сохраняет одно авторское окружение,
а Core вычисляет вид исходников после тех же наложений, которые использует
при адаптации. [Объявление и результат](../reference/javascript-program.md#исходная-композиция-и-отношения)
не требуют отдельных значений для каждой темы.

## Материал и видимый результат

Характер материала проверяется по физическому source RGB. Предпочтение и
`maxChange` относятся к видимому цвету после композиции; расстояние измеряется
в Oklab. Это сохраняет различие
между оранжевым полупрозрачным материалом и серым результатом его наложения
на дополнительный синий фон. Изменение фона не превращает исходник в нейтральный.

Старый режим явной visible-опоры сохраняет свой контракт. Выбор reference-опоры
явно закодирован в Program и входит в идентичность программы. Все адаптеры
передают одну семантику Core.

## Сила и цветовой характер

Пусть `r` — отношение контраста исходного видимого цвета к его исходной
подложке, а `Yb` — относительная яркость текущей подложки. Два возможных
направления переноса задают желаемую яркость:

```text
светлее фона: Y = (Yb + 0.05) × r − 0.05
темнее фона:  Y = (Yb + 0.05) / r − 0.05
```

Core сохраняет исходные координаты Oklab `a/b` и восстанавливает виртуальную
светлоту на верхней монотонной ветви обратного кубического преобразования.
Яркость ограничена физическим диапазоном и минимумом этой ветви; виртуальная
светлота не обрезается до `[0, 1]`. Такая опора может лежать вне sRGB. Её раннее
gamut mapping уничтожило бы сведения о направлении и величине компромисса.
Сторона фона определяется относительной яркостью `Y`, а не координатой Oklab `L`.

Достижимость проверяется по полным допустимым наборам физических цветов.
Один набор должен удовлетворять всем сценариям. Для каждого применения
учитываются фактические подложки во всех сценариях и уже сохраняемые более
приоритетные материалы этого же набора. Нельзя выбирать направление по
достижимости, которую обеспечивает другой фон или изменение более приоритетного
цвета. Для сравнения используется худшая по сценариям доля исходного контраста,
ограниченная единицей.

Среди допустимых наборов Core последовательно сравнивает недостижимость исходной
силы, смещение виртуальной опоры, исходную сторону фона при равенстве и расстояние
до опоры. Это явная политика выбора, а не сумма произвольных весов. Ограничения
контраста и идентичности сохраняют самостоятельный смысл. Явная кривая `tone`
задаёт предпочтительную светлоту и отключает неявное предпочтение исходной силы
для своего применения.

Общий наблюдаемый фон не связывает независимые применения. Физическая зависимость
или объявленное отношение связывают их. Порядок локальных применений определяет
приоритет внутри связанной группы; имена ролей и aliases на него не влияют.

## Объявленная иерархия

`preserveTonalHierarchy` сохраняет исходные отношения `CRstrong / CRweak` соседних
членов группы. Они должны оставаться по одну ненулевую сторону общей подложки;
полная смена стороны допустима. Сравниваются сами отношения. Их натуральные
логарифмы в отчёте служат только объяснению результата.

Это обязательное отношение появляется только из авторской декларации. Core
не знает значений слов `primary`, `secondary` или `tertiary`. Предпочтение силы
одиночного цвета от наличия такой группы не зависит.

## Основания и границы

Формулы относительной яркости и контраста используют определение
[WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html),
а цветовые координаты — [Oklab Бьёрна Оттоссона](https://bottosson.github.io/posts/oklab/).
Нормативная проверка WCAG в Core сохраняет собственные численные границы;
расчёт предпочтения не заменяет решение о её выполнении.

Сохранение исходного отношения контраста и виртуального направления — выбранная
инженерная политика. Указанные источники не доказывают универсальную модель
акцентности, salience или визуальной чистоты. Задача
[контекстной Cleanliness](color-quality.md) остаётся самостоятельной: обоснованное
отношение Cleaner/NotDirtier должно участвовать в том же выборе, с сохранением
неизвестности и несравнимости. Успешный reference transport сам по себе её не решает.
