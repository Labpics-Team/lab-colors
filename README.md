# Lab Colors

Контекстный компилятор цветовых токенов для дизайн-систем.

Lab Colors принимает источники цвета и схему токенов клиента, компилирует их в набор цветовых контрактов и решает весь связанный набор для текущего локального контекста. При смене фона или темы браузерный runtime сначала перепроверяет действующие значения и пересчитывает их только тогда, когда контракт больше не выполняется.

```text
client ThemeConfig
+ собственные имена токенов
+ источники и связи
→ compile
→ NamedRoleTable

NamedRoleTable
+ локальный фон
+ тема
+ output/runtime context
→ resolve
→ значения и статусы всех токенов

context changed
→ recheck
→ keep current values while valid
→ re-resolve when required
```

## Основные свойства

- **Семантика принадлежит клиенту.** Core не понимает слова `primary`, `danger`, `hover` или имена компонентов. Имена ролей приходят из `ThemeConfig`.
- **Значение зависит от контекста.** Один token ID может получить разные физические значения на разных локальных фонах и в разных темах, сохраняя один контракт.
- **Связанные роли решаются вместе с их подложками.** Например, лейбл внутри тонированной заливки проверяется против фактического композита этой заливки, а не против фона страницы.
- **Непрерывные семейства и конечный output разделены.** Кривая предоставляет допустимые состояния, а наружу выходит конечный эмитируемый цвет, который измеряется повторно.
- **Runtime не пересчитывает систему без причины.** `watchTheme` обслуживает дискретные изменения, `adaptTheme` — часто меняющийся фон с дешёвой перепроверкой перед полным resolve.
- **Недостижимость является частью контракта результата.** Невалидный конфиг отклоняется, а физически недостижимая отдельная роль должна возвращаться явно; правдоподобный fallback не является допустимым публичным поведением.

## Не является

Lab Colors не является:

- встроенной дизайн-системой;
- статическим генератором одной палитры из seed-цвета;
- владельцем клиентских названий, уровней и component states;
- универсальной моделью человеческого вкуса;
- автоматическим анализатором изображений, blur и видео;
- доказательством того, что один численный correlate одинаково описывает текст, заливку, границу, материал и пространственный эффект.

## Быстрый старт в браузере

Установите пакет:

```sh
npm install @labpics/colors
```

Загрузите конфиг своей дизайн-системы и примените результат один раз:

```ts
import init, { LabColors, applyTheme } from "@labpics/colors";
import themeConfig from "./theme.config.json";

await init();

const colors = new LabColors();
colors.loadConfig(JSON.stringify(themeConfig));

const result = colors.resolveTheme("#FFFFFF", "light");
applyTheme(document.documentElement, result);
```

Имя темы должно поддерживаться загруженным конфигом и текущим platform adapter. Имена CSS-переменных определяются клиентской схемой.

Для локальной области, фон которой может изменяться:

```ts
import init, { LabColors, watchTheme } from "@labpics/colors";
import themeConfig from "./theme.config.json";

await init();

const colors = new LabColors();
colors.loadConfig(JSON.stringify(themeConfig));

const panel = document.querySelector(".panel");
if (!(panel instanceof HTMLElement)) {
  throw new Error("Элемент .panel не найден");
}

const watcher = watchTheme(panel, {
  colors,
  theme: "light",
});

// Позже:
watcher.setTheme("dark");
watcher.refresh();
watcher.stop();
```

Для анимированного, sampled или часто меняющегося фона используйте `adaptTheme`. Автоматическое чтение DOM поддерживает цепочку `background-color`; для изображения, градиента, blur или видео вызывающая сторона передаёт набор образцов фона явно.

Подробный browser API: [`packages/colors/README.md`](packages/colors/README.md).

## Как устроен продукт

### 1. Клиентская схема

`ThemeConfig` содержит:

- источники и точные anchors;
- клиентские идентификаторы тем и токенов в пределах поддерживаемой схемы и adapter contract;
- aliases;
- рецепты и отношения, необходимые конкретной дизайн-системе.

Конфиг проходит валидацию и компилируется в `NamedRoleTable`. Core не выводит смысл из строки имени.

### 2. Контекстный resolve

`resolve_named_set` / `resolveTheme` получает:

- скомпилированную таблицу;
- текущий локальный фон;
- тему и условия текущего supported profile.

Результат содержит значения и статусы всех ролей. Контракты читаемости, разделения, композитинга и вложенности проверяются в своих единицах; они не смешиваются в общий «балл качества».

### 3. Специализированные цветовые примитивы

Текущая схема использует специализированные рецепты:

| Примитив | Назначение | Не означает |
|---|---|---|
| `TextAnchor` | foreground относительно текущего фона с заданным контрактом | универсальный уровень для любого типа стимула |
| `DjAnchor` | заданное изменение appearance-коррелята относительно фона | читаемость или WCAG |
| `Ladder` | клиентский preset тинта и alpha | закон иерархии generic core |
| `PairFill` / `PairLabel` | зависимая пара «заливка → фактический композит → лейбл» | глобальный фон страницы |
| `Material` | многослойный композит в объявленном профиле | полная модель любого стекла или blur |
| `Glow` | точечный контракт эффекта | пространственное поле после blur |
| `Zero` | явное отсутствие значения | пропущенный ключ |

Имена примитивов описывают физический способ решения. Клиентская семантика остаётся в конфиге.

### 4. Runtime

- `applyTheme` записывает уже решённые CSS custom properties.
- `effectiveBackground` композитит поддерживаемые `background-color` предков.
- `watchTheme` обновляет локальный scope при дискретных изменениях.
- `adaptTheme` выполняет дешёвый recheck и запускает полный resolve только при устойчивом нарушении контракта.

Pure core и stateful runtime-controller остаются разными слоями.

## Источники и производные значения

Точные клиентские anchors и literals являются входными данными. Они не должны незаметно становиться solver variables.

Производные значения могут зависеть от:

- текущего локального фона;
- темы;
- output domain;
- связанного узла;
- выбранного клиентского profile.

Архитектурный контракт требует сохранять provenance каждого производного результата. Alias — второе имя результата, а не отдельная независимо изменяемая копия.

## Непрерывные семейства

`NeutralCurve`, `AccentCurve` и другие реализации `ColorCurve` остаются низкоуровневыми вычислительными примитивами. Они позволяют получать состояние `at(t)` и строить непрерывные family paths.

При этом:

- параметр `t` не является встроенным словарём `Primary / Secondary / ...`;
- одинаковый клиентский уровень разных семейств не обязан иметь одинаковые `t`, `J′`, alpha или hex;
- непрерывный результат не заменяет проверку конечного sRGB/output state;
- текущие gamma, chroma и hue policies рассматриваются как implementation/compatibility policies, пока для них не доказан более сильный статус.

## Контраст и доступность

Нормативный WCAG-контракт и экспериментальные/перцептуальные метрики — разные слои.

- WCAG floor применяется только там, где его явно требует контракт роли.
- Декоративная величина не получает текстовый floor автоматически.
- Экспериментальная метрика не изменяет нормативный pass/fail.
- Цвет не должен быть единственным носителем значения; иконка, текст, форма и component semantics принадлежат дизайн-системе.

## Область поддержки

Базовый продукт поддерживает контекстный resolve точечных и объявленных составных цветовых ролей в поддерживаемых output/profile boundaries.

Границы должны задаваться явно:

- `effectiveBackground` не извлекает один «правильный цвет» из изображения, градиента, blur или видео;
- для неоднородного фона вызывающая сторона передаёт образцы;
- point-glow не сертифицирует spatial blur;
- platform color management, HDR/WCG и user-agent overrides требуют отдельной capability и не предполагаются молча;
- `Preserve / Audit / Project` относятся к отдельному optional Screen ColorQuality layer; они не являются частью обязательного базового resolve и не заменяют его.

## Проверки

Основной локальный набор:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
```

Изменения browser/WASM/public wire contract дополнительно требуют сборки пакета, JS/browser tests и platform conformance. Полный набор обязательных gates определён workflow-файлами репозитория и acceptance конкретного Issue.

## Разработка

Постоянные правила: [`AGENTS.md`](AGENTS.md).

Ключевой принцип:

```text
Дизайн-система задаёт язык, источники и намерения.
Lab Colors компилирует их в проверяемые цветовые контракты.
Runtime поддерживает эти контракты при изменении локального контекста.
```
