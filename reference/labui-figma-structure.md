## 3. Метод вычисления dJ' (точный путь движка)

dJ' роли — модуль разности перцептивной светлоты J' (CAM16-UCS) между
композитом роли и её фоном, под viewing conditions темы:

```
dJ' = |J'(композит роли) − J'(фон)|
```

1. **Композит.** Straight-alpha поверх фона в gamma-кодированном sRGB —
   попарно по каналам `c = a·fg + (1−a)·bg` — так композитит Figma на
   канвасе; результат квантуется до 8-битного hex (цвет, который реально
   показывает дисплей). Это согласуется с движком: `solve::solve_dj`
   честно меряет достигнутый dJ' на квантованном hex (шаг 4 его протокола).
2. **J'.** Точный путь движка: `solve::jp_of_linear` →
   `LcsColor::from_xyz_with_hok(srgb_to_xyz(rgb_linear), 0.0, vc).jp`, то
   есть CIECAM16 forward (`cam16::forward`) → UCS-рескейл `cam16::ucs_j`:
   `J' = 1.7·J / (1 + 0.007·J)` (Li et al. 2017, DOI 10.1002/col.22131).
   Член Хельвига H-K в этом пути не участвует (`h_ok = 0`, и `jp` от него
   не зависит). Публичный эквивалент того же пути —
   `LcsColor::from_hex_with_vc(hex, vc).jp` — используется скриптом
   воспроизведения.
3. **Viewing conditions.** Light-режим — `ViewingConditions::srgb()`
   (D65, L_A = 64 cd/m², Y_b = 20 %, average surround: F = 1.0, c = 0.69,
   N_c = 1.0). Dark-режим — `ViewingConditions::dim_surround()`
   (то же, но dim surround: F = 0.9, c = 0.59, N_c = 0.9) — ровно та VC,
   под которой движок резолвит тёмную тему и по которой
   `DjMagnitude::for_vc` выбирает тёмный якорь (`is_dark_theme()`).

Воспроизведение одной командой:
`cargo run -p labcolors-core --example figma_anchor_provenance`
(входные данные скрипта — сырые значения §2, математика — публичный API
движка; никакой второй копии формул).

## 5. Отношения dark/light (вход для вывода surround-компенсации)

Комментарий в `semantic.rs` упоминает «тёмные якоря примерно в 2.2 раза
больше светлых». Фактические отношения по каждой паре:

| константа | dJ' light | dJ' dark | dark/light |
|---|---|---|---|
| `FILL_PRIMARY_DJ` | 7.9335 | 17.6677 | 2.227 |
| `FILL_SECONDARY_DJ` | 6.4064 | 15.7834 | 2.464 |
| `FILL_TERTIARY_DJ` | 4.6300 | 12.0082 | 2.594 |
| `FILL_QUATERNARY_DJ` | 3.1514 | 8.2190 | 2.608 |
| `BORDER_BASE_DJ` | 6.4064 | 10.1201 | 1.580 |
| `BORDER_SOFT_DJ` | 3.1514 | 5.8273 | 1.849 |

Отношение — не константа: 2.23–2.61 у fill-лестницы и 1.58–1.85 у
border. «примерно 2.2 раза» точно только для `FILL_PRIMARY_DJ`. Отношение
смешивает два независимых фактора: (а) дизайнерский выбор больших альф в
тёмной теме Figma (fill: 36/32/24/16 % против 20/16/12/8 %; border:
20/12 % против 16/8 %) и (б) физику появления — тот же стимул под dim
surround даёт другой J'. Будущий вывод surround-компенсации из CIECAM16
должен разделить эти факторы, а не аппроксимировать их одним множителем.
