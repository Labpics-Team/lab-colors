# Объявленная конечная номинальная модель v2

Это новый научно вычислительный выпуск `exact-nominal-srgb8-point-clean-set-v2`.
Он поддерживает только `DeclaredPackagePolicyCandidate` для
`ModeledSrgb8Point`. Он не создаёт человеческую, физическую или renderer
валидацию. Сам по себе вычислительный PASS не разрешает production admission.

## Первичные данные и явные предпосылки

Sato и Inoue (2016), DOI `10.7717/peerj.2751`: исходные Data S1 и Table S1,
а также XML статьи включены побайтно. Парсер принимает 72 файла cleanliness,
36 участников, две сессии и 32 стимула: всего 2304 ответа. Первый token принят
за идентификатор стимула, второй — за ответ 0..10 с двумя десятичными знаками.
Явного авторского кодбука столбцов нет. Эти роли поддержаны путями, доменами
и описанием процедуры; третий token не участвует в вычислении.

Две сессии усредняются внутри каждого участника, затем участники получают
равный вес внутри каждой отдельной NTF/NTM/CVD когорты. Арифметика точная,
без округления и импутации. Направление шкалы принято как 0 = clean,
10 = dirty. Свидетельства **нечистоты** — 48 пар `(cohort, stimulus)`,
чьё среднее `>= 5`. Это постфактум выбранная политика, не независимый holdout.

Связь raw ID с 32 именованными xyY-строками Table S1 условна. Независимый
полный поиск совместных биекций code→name и raw ID→label использует все
опубликованные CVD naming ограничения плюс одну из двух normal-green опор.
Для каждой опоры и обеих погрешностей печатного процента (±0.5 и ±1 п.п.)
получается ровно одна и та же биекция. Предположения: первый naming token —
ID, четвёртый — код ответа; обе сессии объединены; NTF и NTM объединены для
normal; неопубликованные частоты ниже 15%. Порядок кнопок и порядок строк
не являются предпосылками поиска. Все ограничения опубликованной Table 3
совместно **несовместимы**: этот конфликт сохраняется, а не исправляется.
Полученная связь не объявляется авторским кодбуком или физической калибровкой.

Сохраняется и отдельное расхождение для light yellow: десятая строка данных
`Data S1/dataset_ver2/exp2_stimuli.txt` содержит XYZ `(75.34,78.85,42.04)`,
откуда xy точно равно `(7534/19623,7885/19623)`
(приблизительно `(0.383937,0.401824)`), тогда как строка light yellow
в Table S1 задаёт xyY `(0.22,0.51,75.50)`. Новая модель намеренно использует
буквальные значения Table S1 как объявленные номинальные параметры.
Причина расхождения и физическая идентичность стимула не установлены;
ни опечатка, ни исправление или подтверждение калибровки, ни перенос на
физический дисплей здесь не утверждаются.

CIE CMF 1931 2° (`10.25039/CIE.DS.xvudnb9b`) и D65
(`10.25039/CIE.DS.hjfjmt59`) включены вместе с официальными метаданными.
Их полные исходные CSV проверяются по официальным SHA-256 и MD5. Модель
берёт 421 точку 360..780 нм, шаг 1 нм, единичные веса, без интерполяции,
усечения значений или измерительной неопределённости. Это дискретная
номинальная модель, не полный непрерывный спектр и не заявление о
соответствии всему стандарту ISO/CIE. D65 CSV начинается с 300 нм;
несогласованное начало 360 в одном поле метаданных сохранено как исходное.

## Точный вывод

Пусть `v_i = D65_i * (xbar_i,ybar_i,zbar_i)` и
`Z = {sum rho_i*v_i : 0 <= rho_i <= 1}`. Все величины рациональны.
Table S1 преобразуется формулой `(X,Y,Z)=(xY/y,Y,(1-x-y)Y/y)`.
Для каждой из 32 source-точек проверяется primal/dual сертификат максимума
`mu`, при котором `mu*q` принадлежит Z; `B(q)=1/mu`.
Политическая граница `T` — максимум B по 48 свидетельствам нечистоты.

Номинальный sRGB8-мост использует **точные dyadic значения binary64**
256 decode-литералов и девяти коэффициентов матрицы, закреплённых в исходном
Rust-коде, с масштабом 100: `q=100*M*decode(rgb)`.
Независимый аудит проверяет полный lexical census и nearest-even перевод
каждого десятичного литерала в binary64 через целочисленное разложение битов.
Это не идеальная алгебраическая формула IEC и не измеренный вывод дисплея.

Текущий снимок Rust закреплён на product commit
`e579f73135d359e3d40efdf959aca7d72b600608`: в настоящем исходном тесте
ошибка декодирования передаётся через `Result` вместо `unwrap`.
Все 265 научных литералов, их точные dyadic значения и сертификаты
сохранены. Предыдущие source commit/blob/SHA и точный перечень изменений
метаданных находятся в `SOURCE-PROVENANCE.json`; исторические снимки не
переименовываются в новые. Изменённые JSON являются документами с обновлённой
привязкой к источнику при прежних математических сертификатах, а не
побайтными оригиналами прежнего generator run.

Для ненулевых направлений проверяются positive-ray сертификаты. При них
`B(q)>T` эквивалентно `q/T` вне Z. Равенство отклоняется. Точная нейтральная
ось `r=g=b`, включая чёрный, добавляется в Accepted отдельной объявленной
политикой. В каждой `(r,g)` колонке исключённые blue значения образуют
замкнутый интервал `[lo,hi]`; единственный код пустоты — `255/0`.

Проверяющий код вычисляет опору `h(n)=sum max(0,n·v_i)` самостоятельно.
Две опорные плоскости ограничивают колонку; пересечение ниже/выше границ
невозможно по опорным неравенствам. Для непустого интервала точные допустимые
primal решения на обеих границах доказывают принадлежность между ними по
выпуклости. Поэтому полнота списка найденных автором граней не требуется.
Проверяются 65 536 колонок, 87 558 endpoint равенств и все 16 777 216 RGB
исходов, включая payload отклонения. Канонический LPCC version 1 кодек
строится независимым encoder и декодируется обратно в ту же raw таблицу.

## Воспроизведение и границы вывода

Только Python 3.10+ standard library, сеть и внешние checkout не нужны.
Для standalone-запуска перейдите в каталог, содержащий этот
`NOMINAL-SPEC.md` и `verify_bundle.py` (сам каталог капсулы):

```sh
python3 -I -B verify_bundle.py --output-dir /tmp/nominal-v2-replay --mode both
```

Путь результата можно заменить любым новым каталогом; он должен отсутствовать.
Из корня **публичного product checkout** используйте его путь к капсуле
и явно свяжите проверку с текущими Rust-источниками этого checkout:

```sh
python3 -I -B proof/clean-set-srgb8/v2/verify_bundle.py \
  --output-dir /tmp/nominal-v2-product-replay --mode both --product-root .
```

Standalone-запуск из каталога капсулы не требует `--product-root`.
Если этот параметр передаётся из другого рабочего каталога, укажите абсолютный
путь к корню product checkout; `.` означает именно текущий рабочий каталог.
Научные текстовые файлы читаются и записываются явно в UTF-8; выходные
JSON используют LF независимо от locale и платформенного перевода строк.
Обычный Python и `-O` должны дать одинаковые исходы. Проверки используют
явные исключения, не отключаемые `assert`. Тестируются 11 предметных мутаций
geometry gates, пять повреждений raw input и 529 соседних ошибочных битовых
паттернов bridge; это целевые отрицательные проверки, не универсальный
mutation score и не 11 повторных проходов всей геометрии.

v2 принимает 8 342 111 RGB, отклоняет 8 435 105. Raw SHA-256:
`cf42419977850c435ede3e5be05a0a74b14ad98255418aac7d396f5bb501550e`.
Кодек SHA-256:
`ad4a72b6e3b18950f38544d19998052abf9ab6e12387613eed4ad0d83dfa4a8f`.

Историческая derivation v1/ac6d965 не восстановлена. Сохранены её публичные
runtime bytes и pin для точного сравнения: 109 262 Rejected→Accepted,
0 Accepted→Rejected, 7 483 302 изменения interval payload при сохранённом
Rejected и 9 184 652 полностью неизменных исхода. Известен лишь этот
выходной delta; причинный delta старых матриц/порогов/источников неизвестен.
v2 не объявляется восстановлением v1, исправлением её научной ошибки или
улучшением человеческого восприятия. Старые ID должны отвергаться текущим
одновладельческим runtime после явного перехода на новый release ID.

Не доказаны: author-explicit source identity, измерительная uncertainty,
holdout transfer, универсальная чистота цвета, HCE, multi-color/context
применимость, renderer пригодность или весь production review.
